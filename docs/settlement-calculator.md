# Расчёт взаиморасчётов

`SettlementCalculator.Calculate(trip)` строит итоговые переводы по всем расходам поездки.
Он ничего не изменяет в `Trip` и при повторном вызове возвращает тот же результат.

Баланс каждого участника рассчитывается по формуле:

```text
balance = оплаченные расходы - доли в расходах
```

Положительный баланс означает, что участник должен получить деньги. Отрицательный —
что он должен заплатить. Сумма всех балансов обязана быть равна нулю.

Баланс внутри калькулятора хранится в целых копейках на `BigInteger`. Это исключает
переполнение и потерю копеек при накоплении большого количества расходов.

После расчёта балансов участники разделяются на кредиторов и должников. Для текущей
пары рассчитывается сумма:

```text
amount = min(остаток долга, остаток кредита)
```

Если сумма точно помещается в `decimal`, для пары создаётся один перевод. Если общий
долг пары больше предела `decimal` или не может быть представлен им без потери копеек,
он разбивается на несколько переводов между теми же участниками. Затем погашенная
сторона заменяется следующей. Участники обрабатываются в порядке, в котором они
добавлены в поездку, поэтому результат стабилен. Каждый перевод содержит
`FromParticipantId`, `ToParticipantId` и `Amount`; имена участников может добавить
Application или API при формировании ответа.

Пример балансов:

```text
Ivan   +40
Oleg   -10
Masha  -30
```

Результат:

```text
Oleg  -> Ivan  10
Masha -> Ivan  30
```

Для сумм, представимых одним `decimal` на каждую пару, жадный алгоритм создаёт не более
`creditors + debtors - 1` переводов. Дополнительные переводы появляются только при
разбиении экстремально больших сумм. Алгоритм хорошо упрощает взаиморасчёты, но не
гарантирует абсолютный математический минимум количества переводов для каждой возможной
комбинации балансов: поиск такого минимума требует отдельного, существенно более
сложного алгоритма.
